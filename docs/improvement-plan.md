# 시니어서포트(senior.zucca100.com) 개선 계획서

> **상태:** 승인 대기. "구현 시작" 지시 전까지 코드 수정 금지. 이 문서는 구조 파악·조사·설계만 담는다.
> **대상:** `com.jiwongum.app` 웹뷰 앱이 로드하는 웹(`web/`, Next.js 15, senior.zucca100.com) + 필요한 네이티브 연동 지점.

## 0. 판단 기준 (모든 결정의 상위 규칙)

- **정체성:** "들어가서 5초면 볼일 다 보고 나오는 앱. 대신 365일 접속할 이유가 있는 앱."
- **타겟:** 50~70대+, 키오스크도 어려운 수준. '읽는' 게 아니라 '알아보는' 화면.
- **핵심 원칙 4:** ① 원클릭(도달 탭 ≤2회) ② 요점만 크게(한 화면 정보블록 ≤3, 여백보다 글자) ③ 색으로 구분(라벨 아닌 색상 블록+아이콘) ④ 기능 추가 금지(넣으려면 하나 빼라)

### 1-2. 컴포넌트 / 데이터

- `web/app/seniorArticles.js` (347줄) — **정적 배열 17개**. 그룹: 연금·노후소득(5), 건강·돌봄(5), 가족 대신 확인(3), 생활비·공공요금(3), 일자리·활동(1). 각 글은 외부 공식 URL로 연결.

### 1-3. 데이터 흐름

- **정적 콘텐츠:** `seniorArticles.js` 배열 → 홈/Explorer에서 직접 렌더. 서버 호출 없음.
- **커뮤니티:** 브라우저 → `communitySupabase`(anon) → Supabase 직접 read/write. RLS가 접근 제어. 클라이언트 UUID(`localStorage`)로 좋아요 중복 방지.
- **외부 지원금 데이터: 현재 없음.** 모두 손으로 채운 17개 글. (요구사항 A가 이 공백을 메운다.)

### 1-4. 광고 배치 현황 ⚠️

- 광고 방식 = **AdSense Auto Ads**. `layout.js`에서 `adsbygoogle.js` **스크립트만** 로드. 수동 `<ins class="adsbygoogle">` 슬롯은 **웹 전체에 0개**(grep 확인).
- 즉, 광고 **위치를 게시자가 제어하지 않음**. Google이 자동으로 ▸앵커(Anchor, 하단 고정) ▸비녜트(Vignette, 화면 전환 시 전면) ▸본문 삽입 광고를 꽂는다.
- 웹뷰 앱 하단에는 **네이티브 탭바**(홈/선발대/설정, `App.js:39-77`)가 있음. AdSense 앵커 광고가 이 탭바 바로 위에 붙어 → **오탭**. 비녜트는 탭/링크 전환 직후 떠서 → **탭 관성 오탭**. (요구사항 E의 실제 원인.)
- 웹은 AdSense(`ca-pub-9196149361612087`), 네이티브 앱은 AdMob(`ca-app-pub-8785405056367250`)로 **계정이 분리**돼 있음. 웹뷰가 `registerWebViewForAds`로 둘을 브릿지.

## 3. 공공 API 조사 결과

> 공통: 전부 **공공데이터포털(data.go.kr)** 제공. **인증키(서비스키) 발급 필요** — data.go.kr 로그인 후 해당 데이터에서 "활용신청". 개발계정은 대개 자동승인(트래픽 제한), 운영계정/트래픽 확장은 활용사례 등록 후 승인. **키는 사용자가 발급**해야 함(아래 ★ 표시).
> 공통 제약(보조금24 페이지에서 확인): REST, **JSON+XML**, 개발계정 **10,000회/일**, 운영 확장 가능, **초당 호출 제한**(초과 시 에러코드 23).
> ⚠️ data.go.kr 상세 페이지가 JS 렌더링이라, **오퍼레이션/파라미터의 정확한 문자열은 발급 후 각 데이터의 "OpenAPI 명세(Swagger)"에서 최종 확정** 필요. 아래 파라미터명은 복지로 계열 관례 기준의 **유력 후보**로 표시.

### ✅ 사용 가능 + ★키 발급 필요

| # | API (데이터셋) | 제공기관 | 검색 방식 | 적합도 |
|---|---|---|---|---|
| 1 | **중앙부처복지서비스** `15090532` | 한국사회보장정보원 | **키워드 자유검색**(검색어 파라미터, 유력: `searchWrd`) + 목록/상세 오퍼레이션 | ★★★ 키워드 검색에 최적 |
| 2 | **지자체복지서비스** `15108347` | 한국사회보장정보원 | **키워드 + 지역 필터** + 목록/상세 | ★★★ 지역(재방문 기능②)과 결합 |
| 3 | **대한민국 공공서비스(혜택) 정보(보조금24)** `15113968` | 행정안전부 | 목록(주로 코드/조건 필터) + 상세(서비스ID). 자유검색 파라미터 **불명확** | ★★ 커버리지 최광, 폴백 |

- **응답 필드(공통, 유력):** 서비스ID(`servId`), 서비스명(`servNm`), 요약(`servDgst`), 소관기관(`jurMnofNm`/`jurOrgNm`), 지원주기, 제공유형, 신청방법, 상세조회 링크. — 카드 렌더에 충분.
- **CORS:** data.go.kr는 브라우저 CORS 헤더 미제공 → **반드시 Next 서버 라우트(`/api/search`)에서 프록시**. 이 설계로 서비스키도 서버에만 둔다(`process.env.DATA_GO_KR_KEY`, `NEXT_PUBLIC_` 아님).

### ⚠️ 사용 가능하나 실시간 아님

| API | 형태 | 비고 |
|---|---|---|
| **민간복지서비스정보** `15116392` | 파일데이터(다운로드) | 실시간 조회 API 아님. 보완용 시드 데이터로만 고려 |

### ❌ 현재 부적합 / 확인불가

- 정부24 `/openapi`의 나머지(민원 통계, 보조금24 통계 등) — **집계 통계**라 지원금 검색 부적합.
- data.go.kr 상세 스펙(정확한 파라미터 문자열)은 페이지 JS 차단으로 **문서만으로 확정 불가** → 키 발급 후 Swagger에서 확정(위 ⚠️).

### 권장안 (A 구현)

1차 = **① 중앙부처복지서비스 + ② 지자체복지서비스**. 사용자가 입력한 한 단어(또는 자주찾는 버튼 키워드)를 검색어 파라미터로 그대로 전달 → 목록 수신 → 카드. 지역은 ②에서 필터(재방문 기능②와 결합). **보조금24(③)**는 커버리지 넓지만 자유검색이 불확실하니 2차/폴백.

### ★ 사용자 조치 필요 (키 발급)

- data.go.kr 계정으로 **`15090532`, `15108347`(필요 시 `15113968`)** 각각 "활용신청" → 발급된 **일반 인증키(Encoding/Decoding)** 를 전달해주면 서버 env(`DATA_GO_KR_KEY`)에 설정. **개발 중엔 개발계정 키(10,000회/일)로 충분**, 배포 시 운영계정 신청.

## 4. 재방문 기능 2개 선정안 + 근거

> 선정 기준: **구현 난이도 대비 재방문 기여도.** 4개 중 2개만 채택(원칙 ④ 기능 최소화).

### ✅ 채택 1 — 오늘의 혜택 1건 고정 노출

- **난이도: 최저.** 날짜(YYYY-MM-DD) 해시로 후보 배열에서 결정적 1건 선택. 새 인프라 0, 기존 `seniorArticles.js`/검색 API 재사용.
- **기여도: 높음.** 매일 바뀌는 "오늘의" 1건 = 매일 열 이유(습관화). 정보블록 1개·크게 = 시니어 원칙(②)과 정면 부합. "5초면 볼일 끝"과도 일치.

### ✅ 채택 2 — 내 조건(나이·지역) 저장 후 자동 필터

- **난이도: 낮음.** localStorage에 나이대·지역 저장 → 검색/오늘의 혜택에 지역 파라미터 반영. 온보딩이 **이미 지역·상황을 저장**(`OnboardingScreen.js`, `storage.js`) → 규약만 맞추면 자산 재사용.
- **기여도: 높음.** "나에게 해당되는 것만" = 개인화된 재방문 동기. 타이핑 부담↓(원클릭 원칙). 지자체복지서비스 API의 지역 필터와 자연 결합.

### ❌ 제외 — 신규/마감임박 배지

- 검색 API 응답의 **신청기한 데이터 신뢰도·커버리지 불확실**(항목마다 상시/미기재 다수). 파싱·검증 비용 대비 기여 불확실 → 난이도 대비 리스크 큼.

### ❌ 제외 — 카카오 채널 연동 알림

- 카카오 비즈메시지 **채널 개설·심사·발송 비용·정책** 필요(외부 의존·고난이도). 요구사항 B의 카카오 링크와 **역할 중복**. 지금 단계 부적합.

## 5. 구현 순서와 단계별 체크포인트

> 각 단계는 독립 배포 가능한 단위. 단계 끝 = 체크포인트에서 검증 후 다음.
> "구현 시작" 지시 후 착수. 각 단계 완료 시 사용자 확인.

**0단계 — 사전 조건 (사용자)**
- [ ] data.go.kr에서 `15090532`, `15108347` 활용신청 → 인증키 확보
- [ ] 체크포인트: 키로 `curl` 목록 호출 1건 성공(JSON 200) 확인 → 실제 파라미터/필드 문자열 확정

**1단계 — 광고 안전화 (E, 리스크 최소·독립)**
- [ ] AdSense Auto Ads의 Vignette·Anchor 포맷 OFF, `layout.js` 정리
- [ ] 체크포인트: 웹뷰에서 탭 전환·스크롤 시 전면/하단고정 광고 미출현, 네이티브 탭바 오탭 재현 안 됨

**2단계 — 커뮤니티 제거 + 카카오 링크 (B)**
- [ ] `/community`·`CommunityBoard` 삭제, 홈 프리뷰 → "궁금한 점 물어보기" 버튼 2개
- [ ] `App.js` Community 탭 동반 처리(제거 또는 재지정), sitemap 갱신
- [ ] 체크포인트: 앱 3탭 정상, 카카오 채널/오픈채팅 링크 외부 정상 오픈, 커뮤니티 잔재 라우트 없음(404 없음)

**3단계 — 검색 백엔드 (A-1)**
- [ ] `/api/search` 라우트: 서버키로 공공 API 프록시, 응답 정규화(서비스명/요약/기관/상세링크)
- [ ] 체크포인트: `기초연금`·`난방비` 등 질의에 결과 반환, 키가 클라이언트 번들에 없음(빌드 산출물 grep)

**4단계 — 검색 화면 (A-2)**
- [ ] `/search`: 자주찾는 키워드 대형버튼 5개(기초연금/의료비/주거/일자리/난방비) → 입력창1+버튼1 → 결과 카드
- [ ] 체크포인트: 버튼 원탭 검색 동작, 결과까지 탭 ≤2회, 필터/정렬/고급검색 없음

**5단계 — 재방문 기능 (C)**
- [ ] 오늘의 혜택 고정 블록 + 내 조건(나이·지역) 저장/필터
- [ ] 체크포인트: 날짜 바뀌면 오늘의 혜택 변경, 지역 저장 시 결과 반영, 재방문 시 조건 유지

**6단계 — 시니어 UI 개편 (D)**
- [ ] 본문 ≥20px/제목 ≥28px/터치 ≥56px/AAA 대비/카테고리 색상블록+아이콘 전면 적용
- [ ] 체크포인트: 실제 시니어 흐름 점검(홈→검색→결과 2탭), 대비/터치 자동 점검 통과, 시스템 글꼴 배율 반영

## 6. 리스크

### 심사(Google Play / AdSense) 영향
- **웹뷰 최소기능 정책:** 커뮤니티 삭제로 상호작용 기능이 줄면 "단순 웹뷰" 지적 가능성 ↑. → 검색(A)·오늘의 혜택·조건저장(C)이 **네이티브적 실질 기능**으로 이를 상쇄하도록 배치(완화책).
- **AdSense 정책:** Vignette/Anchor OFF는 정책 위반이 아니라 **오탭(무효 트래픽) 리스크를 낮춤**(오히려 안전). 수동 슬롯 도입 시 콘텐츠와 광고 명확 구분·라벨 필수.
- **공공 API 이용:** 출처 표기·"참고용, 최종은 공식기관 확인" 고지 유지(기존 disclaimer 재사용). 운영 트래픽은 운영계정 승인 전까지 10,000회/일 한도 → 캐싱 필요.

### 기존 사용자 영향
- **커뮤니티 데이터:** 삭제 시 기존 글/댓글 접근 불가. Supabase `community_*` 테이블 **물리 삭제는 별도 승인 항목**(우선 비노출→관찰 후 삭제 권장, 롤백 여지 확보).
- **네이티브 탭 변경:** 기존 사용자 홈에서 "선발대" 탭이 사라짐 → 앱 업데이트 후 첫 진입 혼선 가능. 탭 라벨/동선 명확히.
- **URL 변경:** `/community` 제거로 외부 유입/북마크 404 가능 → 홈 리다이렉트 처리 검토.
- **API 의존:** 공공 API 장애/지연 시 검색 빈 결과 → 폴백(정적 `seniorArticles` 노출)·로딩/오류 UI 필수(앱 웹뷰 오류화면과 일관).
